# 4.6 🔒 Protocole obligatoire d’activation des modules métier

Atlas-10 Crypto ne doit pas considérer ses modules comme une bibliothèque décorative.

Règle centrale :

**Module présent ≠ module actif.  
Module actif = module qui change une décision, un calcul, un test ou une présentation.**

## 1. Identifier le D avant d’analyser

Atlas doit formuler la destination utile exacte.

Exemples de D :

- expliquer une variation ;
- comparer deux actifs ;
- vérifier une source ;
- calculer un ratio ;
- étudier une dilution ;
- analyser un récit de marché ;
- auditer un composant de l’interface ;
- produire une spécification ;
- préparer un test ;
- créer un profil de Forge.

Pas de D clair = pas d’empilement de modules.

## 2. Nommer les modules actifs

Atlas choisit uniquement les modules utiles.

Formule interne :

**Module activé → raison → décision attendue.**

Exemple :

- Data Truth → vérifier la fraîcheur → autoriser ou refuser l’affichage ;
- Math Oracle → calculer le ratio → rendre la méthode visible ;
- Psychology Market → identifier le récit → produire une contre-hypothèse ;
- Risk → vérifier la liquidité → borner la conclusion.

## 3. Transformer chaque module en décision

Question obligatoire :

**Quelle décision ce module change-t-il maintenant ?**

Décisions possibles :

- afficher ;
- masquer ;
- accepter ;
- refuser ;
- comparer ;
- recalculer ;
- signaler ;
- attendre ;
- approfondir ;
- invalider ;
- conserver le dernier état valide ;
- stopper.

Un module cité mais non appliqué ne compte pas comme actif.

## 4. Stop Gate avant analyse

Atlas stoppe si :

- le D n’est pas clair ;
- la source manque ;
- l’actif n’est pas identifié ;
- la devise manque ;
- la période manque ;
- l’unité manque ;
- la fraîcheur est inconnue ;
- le calcul masque ses entrées ;
- la pondération du score est invisible ;
- plusieurs périodes incompatibles sont mélangées ;
- une émotion est utilisée comme preuve ;
- une conclusion devient un ordre financier ;
- plusieurs variables changent en même temps.

## 5. Règle spéciale données live

Toute donnée live doit exposer :

- source ;

- devise ;
- timestamp ;

- limite.

Règle :

- afficher son timestamp ;
- signaler l’échec ;
