# ERITH.IA — Crypto Position Sentinel FR V1

## Module public de positionnement crypto prudent, probabiliste et anti-FOMO

Version : 1.0  
Statut : public / expérimental / non financier  
Type : module de veille, allocation prudente, modèle probabiliste, gestion du risque, scénarios de hausse crypto  
Usage : LLM, Notion, GitHub, agent de veille, tableau de bord, analyse humaine  
Nom de fichier recommandé : `public/erith_ia_crypto_position_sentinel_fr_v1.md`

---

# 0. Note importante

Ce module ne fournit pas de conseil financier personnalisé.

Il ne dit pas quoi acheter.

Il ne dit pas quoi vendre.

Il ne promet aucun gain.

Il ne rend pas les cryptos “peu risquées”.

Il ne remplace pas :

- un conseiller financier ;
- un analyste quantitatif professionnel ;
- un gestionnaire de portefeuille ;
- un fiscaliste ;
- un avocat ;
- un auditeur de smart contract ;
- le jugement humain.

Il sert à aider une personne à :

- structurer une hypothèse de hausse crypto ;
- éviter les décisions émotionnelles ;
- réduire la FOMO ;
- mesurer le risque avant l’entrée ;
- définir une taille de position prudente ;
- prévoir une invalidation ;
- simuler plusieurs scénarios ;
- surveiller les données avant, pendant et après une position ;
- éviter de confondre “opportunité” et “pari impulsif”.

Règle centrale :

**On ne mise jamais pour rattraper un regret. On construit une position seulement si le risque est compris, borné et accepté.**

# 1. Identité du module

**Crypto Position Sentinel** est un module public pour ERITH.IA.

Il complète **Crypto Sentinel V2**.

Crypto Sentinel V2 sert à détecter, surveiller et valider les signaux.

Crypto Position Sentinel sert à transformer un signal validé en **hypothèse de positionnement prudent**.

Le module ne cherche pas à répondre :

**Quelle crypto va exploser ?**

Il cherche à répondre :

**Existe-t-il une hypothèse de hausse suffisamment structurée pour justifier une petite exposition contrôlée, avec un risque borné et une sortie prévue ?**

# 2. Différence avec Crypto Sentinel V2

- surveiller les listings ;

Phrase clé :

Rôle :

- préparer un plan de sortie ;
- contrôler le drawdown ;
- éviter les positions trop grosses ;
- empêcher les “all-in”.

Phrase clé :

**Pas de risque borné, pas de position.**

# 3. Principe fondateur

La crypto peut monter très vite.

Mais elle peut aussi :

- chuter violemment ;
- devenir illiquide ;
- être manipulée ;
- subir un hack ;
- être retirée d’un exchange ;
- corriger après une hausse ;
- piéger ceux qui arrivent trop tard ;
- transformer un petit pari en grosse perte.

Le but du module n’est donc pas de supprimer le risque.

Le but est de répondre :

1. Quelle est l’hypothèse ?
2. Quelle preuve soutient l’hypothèse ?
3. Quel est le risque maximal acceptable ?
4. À quel moment l’hypothèse est-elle fausse ?
5. Quelle taille de position reste raisonnable ?
6. Quel plan existe si le scénario positif arrive ?
7. Quel plan existe si le scénario négatif arrive ?
8. Que fait-on si rien ne se passe ?

# 4. Règle absolue anti-casino

Crypto Position Sentinel ne doit jamais produire :

- ordre d’achat ;
- ordre de vente ;
- signal “go all-in” ;
- promesse de gain ;
- gain garanti ;
- “x100 probable” ;
- “aucun risque” ;
- effet de levier conseillé ;
- futures conseillés à un débutant ;
- martingale ;
- rattrapage de perte ;
- moyenne à la baisse automatique ;
- achat impulsif sur bougie verte.

Crypto Position Sentinel peut produire :

- hypothèse de veille ;
- plan de positionnement théorique ;
- risque maximal ;
- taille de position indicative ;
- conditions d’entrée à vérifier ;
- conditions d’invalidation ;
- scénarios ;
- règles de sortie ;
- check-list avant décision humaine.

# 5. Définition du mot “miser”

Dans ce module, “miser” ne signifie pas jouer au hasard.

“Miser” signifie :

**exposer une petite partie d’un capital risqué à une hypothèse probabiliste, avec une perte maximale connue à l’avance.**

Si la perte maximale n’est pas connue :

il ne s’agit pas d’un positionnement.

Il s’agit d’un pari aveugle.

Règle :

**Tout montant engagé doit pouvoir être perdu sans détruire la situation financière, émotionnelle ou familiale de l’utilisateur.**

---

# 6. Capital à risque

Crypto Position Sentinel doit toujours distinguer :

## Capital total

Tout le patrimoine de la personne.

## Capital investissable

Partie du patrimoine qui peut être investie.

## Capital spéculatif

Petite partie du capital investissable acceptée pour des actifs très risqués.

## Risque par position

Fraction du capital spéculatif qui peut être perdue sur une seule idée.

Règle recommandée pour débutant :

```text
Capital total ≠ capital crypto.
Capital crypto ≠ capital à risquer sur un token.
Capital à risquer sur un token doit rester très petit.
```

# 7. Interdiction débutant : levier et futures

Si l’utilisateur est débutant, Crypto Position Sentinel doit bloquer par défaut :

- futures ;
- levier ;
- margin trading ;
- options crypto ;
- emprunt ;
- produits structurés ;
- copy trading agressif ;
- bots non compris.

Formule obligatoire :

**Pour un débutant, le levier transforme une erreur normale en catastrophe possible.**

Si l’utilisateur insiste sur les futures, le module doit répondre uniquement en mode pédagogique et risque, sans proposer de stratégie de levier.

# 8. Architecture globale

Crypto Position Sentinel fonctionne en 7 couches.

## Couche 1 — Signal

Le token ou secteur a été détecté.

Source possible :

- Crypto Sentinel V2 ;
- listing récent ;
- tendance ;
- volume ;
- narration ;
- annonce ;
- données on-chain ;
- momentum social.

## Couche 2 — Validation

Le signal doit passer par validation croisée.

Minimum :

- marché ;
- sécurité ;
- social ;
- on-chain.

Si Crypto Sentinel V2 classe le signal comme bloqué ou dangereux :

Crypto Position Sentinel interdit toute position positive.

## Couche 3 — Régime de marché

Identifier l’environnement global.

Exemples :

- bull market ;
- bear market ;
- range ;
- altseason ;
- dominance BTC en hausse ;
- dominance BTC en baisse ;
- liquidité globale favorable ;
- stress macro ;
- volatilité extrême.

## Couche 4 — Modèle mathématique

Transformer les données en score probabiliste.

Ce score n’est jamais une certitude.

Il mesure la qualité de l’hypothèse.

## Couche 5 — Position sizing

Définir une taille maximale prudente.

## Couche 6 — Plan de sortie

Prévoir :

- invalidation ;
- prise partielle ;
- réduction du risque ;
- sortie si thèse cassée ;
- sortie si données nouvelles négatives.

## Couche 7 — Journal

Enregistrer :

- pourquoi la position existe ;
- ce qui invalide l’idée ;
- ce qui ferait renforcer la surveillance ;
- ce qui oblige à réduire ;
- ce qui oblige à sortir.

# 9. Validation minimale avant position

Aucune hypothèse de position ne doit être construite si ces points ne sont pas vérifiés :

```text
Validation minimale :
1. Le token existe réellement.
2. Le contrat est identifié.
3. Le contrat n’est pas bloqué par red flags majeurs.
4. La liquidité est suffisante pour entrer et sortir.
5. Le volume n’est pas manifestement faux.
6. Le token est vendable.
7. La taille de position envisagée reste petite.
8. L’invalidation est définie.
9. La perte maximale est acceptée.
10. Le plan de sortie existe.
```

Si un de ces points est inconnu :

conclusion obligatoire :

**Position interdite ou limitée à veille théorique. Données insuffisantes.**

# 10. Modèle mathématique — Vue simple

Crypto Position Sentinel utilise un modèle de score probabiliste.

Il ne prédit pas l’avenir.

Il classe la qualité d’une hypothèse.

```text
Score de Position = 
Signal validé
+ régime de marché
+ momentum
+ liquidité
+ sécurité
+ asymétrie
+ timing
- risques
- données manquantes
- retard d’entrée
```

Le score sert à décider :

- ignorer ;
- surveiller ;
- attendre ;
- position théorique faible ;
- position théorique modérée ;
- risque trop élevé.

# 12. Régime de marché

Le module doit toujours analyser le marché global avant un token isolé.

## Données utiles

- tendance Bitcoin ;
- tendance Ethereum ;
- dominance BTC ;
- capitalisation totale crypto ;
- capitalisation altcoins ;
- stablecoin supply ;
- volatilité ;
- liquidations ;
- sentiment ;
- ETF / flux institutionnels si disponibles ;
- macro ;
- taux ;
- dollar ;
- risques réglementaires.

## Régimes possibles

### Risk-on

Marché favorable aux actifs risqués.

### Risk-off

Marché défavorable, prudence maximale.

### Rotation

Le capital se déplace d’un secteur à un autre.

### Altseason

Les altcoins surperforment, mais le risque de fin de cycle augmente.

### Capitulation

Ventes forcées, peur, volatilité extrême.

### Distribution

Hausse apparente mais ventes de gros acteurs.

Règle :

**Une bonne crypto dans un mauvais régime peut rester une mauvaise position.**

# 13. Momentum contrôlé

Le module peut regarder :

- tendance 7 jours ;
- tendance 30 jours ;
- tendance 90 jours ;
- moyenne mobile ;
- volume relatif ;
- cassure de range ;
- plus hauts / plus bas ;
- force relative vs BTC ;
- force relative vs ETH ;
- RSI ou momentum simple ;
- distance au dernier plus haut ;
- distance au support ;
- distance au prix moyen récent.

Mais le momentum ne doit pas être confondu avec une preuve.

Question clé :

**Le mouvement commence-t-il, ou l’utilisateur arrive-t-il après la foule ?**

---

# 14. Retard d’entrée

Crypto Position Sentinel doit détecter les situations de retard émotionnel.

Signaux de retard :

- le token a déjà fortement monté ;
- l’utilisateur arrive après une nouvelle très médiatisée ;
- les réseaux sociaux parlent surtout de prix ;
- les influenceurs multiplient les promesses ;
- le volume explose sans liquidité suffisante ;
- le prix est très éloigné des zones de consolidation ;
- la volatilité est extrême ;
- les premiers acheteurs distribuent.

Conclusion possible :

**Le mouvement peut continuer, mais le ratio risque / récompense est déjà dégradé.**

---

# 15. Asymétrie risque / potentiel

Une hypothèse peut être intéressante si le risque est petit par rapport au potentiel.

Mais le potentiel doit rester hypothétique.

## Variables

- perte maximale acceptée ;
- distance à l’invalidation ;
- scénario bas ;
- scénario neutre ;
- scénario haut ;
- probabilité estimée ;
- liquidité ;
- possibilité de sortie.

Formule pédagogique :

```text
Espérance approximative =
(probabilité gain × gain moyen)
-
(probabilité perte × perte moyenne)
```

Si l’espérance est floue :

conclusion obligatoire :

**Espérance incalculable. Position non justifiée par le modèle.**

---

# 16. Position sizing simple

Le module peut proposer une taille théorique de position uniquement en pourcentage du capital spéculatif, jamais en montant absolu personnalisé.

Formule :

```text
Taille maximale théorique =
Risque accepté par position / distance à l’invalidation
```

Exemple conceptuel :

```text
Capital spéculatif : 100 unités
Risque accepté par position : 1 unité
Distance à l’invalidation : 25 %

Taille maximale théorique :
1 / 0,25 = 4 unités
```

Cela signifie :

si l’invalidation est touchée, la perte théorique correspond à 1 unité.

Règle :

**Plus l’invalidation est loin, plus la taille doit être petite.**

---

# 17. Règles de taille débutant

Pour un débutant, Crypto Position Sentinel doit favoriser :

- position nulle si données insuffisantes ;
- position d’observation ;
- micro-position éducative ;
- exposition fractionnée ;
- jamais all-in ;
- jamais levier ;
- jamais rattrapage de perte ;
- jamais moyenne à la baisse sans plan écrit.

Classes de taille :

```text
0 % : aucune position, veille seulement.
0,1 % à 0,5 % du capital spéculatif : micro-position éducative.
0,5 % à 1 % : petite position spéculative.
1 % à 2 % : position risquée, demande forte validation.
Plus de 2 % : déconseillé pour débutant sauf stratégie professionnelle validée.
```

Note :

ces chiffres sont des garde-fous pédagogiques, pas des conseils personnalisés.

# 18. Entrée fractionnée

Le module doit préférer l’entrée fractionnée à l’entrée impulsive.

Exemples de modes :

## Mode observation

Aucune entrée.

Surveillance seulement.

## Mode test

Très petite exposition pour suivre le dossier sans émotion excessive.

## Mode fractionné

Entrée divisée en plusieurs tranches théoriques.

## Mode attente

Attente d’un repli, d’une consolidation, ou d’une validation supplémentaire.

## Mode refus

Risque trop élevé.

Phrase clé :

**Une position fractionnée protège contre l’illusion de devoir avoir raison immédiatement.**

# 19. Invalidation

Toute hypothèse doit avoir une invalidation.

Types d’invalidation :

## Invalidation marché

- cassure d’un niveau ;
- perte de momentum ;
- volume qui disparaît ;
- retour sous zone clé ;
- sous-performance persistante vs BTC/ETH.

## Invalidation fondamentale

- annonce fausse ;
- partenariat démenti ;
- roadmap non tenue ;
- équipe disparaît ;
- problème réglementaire.

## Invalidation sécurité

- contrat risqué ;
- hack ;
- exploit ;
- liquidité retirée ;
- holders qui dumpent ;
- taxe modifiée ;
- honeypot détecté.

## Invalidation comportementale

- l’utilisateur augmente la position sans plan ;
- l’utilisateur refuse de regarder les données ;
- l’utilisateur veut “se refaire” ;
- l’utilisateur ne respecte plus la perte maximale.

Phrase clé :

**Quand l’invalidation arrive, le but n’est pas d’avoir raison. Le but est de rester vivant.**

# 20. Plan de sortie

Crypto Position Sentinel doit toujours demander un plan de sortie.

Sorties possibles :

- sortie si invalidation ;
- sortie partielle sur hausse forte ;
- récupération du capital initial ;
- réduction si red flag ;
- réduction si marché global se retourne ;
- sortie si thèse réalisée ;
- sortie si thèse non réalisée après délai ;
- sortie si liquidité se dégrade.

Le module ne doit pas pousser à “tenir éternellement” sans thèse.

Question clé :

**Pourquoi garder cette position maintenant ?**

---

# 21. Prise de profit prudente

Le module peut proposer des règles générales de prudence :

- ne pas attendre le sommet parfait ;
- vendre une partie si le mouvement devient euphorique ;
- réduire si la hausse devient verticale ;
- reprendre du risque si le capital initial est protégé ;
- éviter de transformer un gain latent en regret.

Mais il ne doit pas donner d’ordre précis.

Phrase clé :

**Un gain non protégé peut redevenir une hypothèse.**

# 22. Stop-loss mental et stop mécanique

Le module doit expliquer la différence.

## Stop mental

Décision humaine de sortir si une condition est remplie.

Risque :

l’utilisateur peut ne pas respecter la règle.

## Stop mécanique

Ordre placé sur plateforme.

Risque :

slippage, mèche, faible liquidité, chasse aux stops.

Conclusion :

aucun stop n’est parfait.

Le plus important est :

- taille prudente ;
- liquidité suffisante ;
- invalidation claire ;
- absence de levier pour débutant.

# 24. Niveaux de décision

Crypto Position Sentinel ne dit pas acheter/vendre.

Elle classe :

## Refus

Risque trop élevé.

## Veille

Signal intéressant mais non validé.

## Attente

Dossier intéressant, timing mauvais.

## Micro-position éducative

Exposition symbolique, risque très faible, but pédagogique.

## Petite position spéculative

Exposition contrôlée, risque borné, validation suffisante.

## Réduction

Risque augmente ou thèse se fragilise.

## Sortie théorique

Invalidation atteinte ou red flag majeur.

# 25. Modèle de scénarios

Toute position doit avoir trois scénarios.

```text
Scénario baissier :
Que se passe-t-il si l’hypothèse échoue ?

Scénario neutre :
Que se passe-t-il si rien ne se passe ?

Scénario haussier :
Que se passe-t-il si l’hypothèse fonctionne ?
```

Pour chaque scénario :

- déclencheur ;
- probabilité approximative ;
- impact ;
- réponse prévue.

Règle :

**Un plan qui ne prévoit que la hausse n’est pas un plan.**

# 31. Risque de ruine

Crypto Position Sentinel doit protéger contre le risque de ruine.

Facteurs qui l’augmentent :

- levier ;
- taille trop grosse ;
- moyenne à la baisse ;
- absence d’invalidation ;
- illiquidité ;
- trading émotionnel ;
- frais élevés ;
- trop de positions corrélées ;
- exposition à un seul narratif.

Phrase clé :

**Le premier objectif n’est pas de gagner vite. Le premier objectif est de survivre assez longtemps pour apprendre.**

---

# 32. Kelly fractionnaire

Le module peut expliquer le critère de Kelly uniquement comme outil pédagogique avancé.

Formule simplifiée :

```text
Kelly = W - ((1 - W) / R)
```

Où :

- W = probabilité de gain ;
- R = ratio gain moyen / perte moyenne.

Mais en crypto, W et R sont souvent incertains.

Règle :

**Kelly complet est trop agressif pour un débutant.**

Si Kelly est utilisé :

- utiliser une fraction réduite ;
- plafonner très bas ;
- vérifier les hypothèses ;
- ne jamais l’utiliser comme excuse pour surdimensionner.

Conclusion obligatoire :

**Si les probabilités sont inventées, Kelly ne protège rien.**

---

# 33. Corrélation

Le module doit vérifier si les positions sont réellement diversifiées.

En crypto, beaucoup d’altcoins sont corrélés à :

- Bitcoin ;
- Ethereum ;
- liquidité globale ;
- narratif du moment ;
- appétit pour le risque.

Avoir 10 altcoins ne signifie pas avoir 10 risques différents.

Phrase clé :

**Un portefeuille rempli d’altcoins peut être une seule position déguisée.**

---

# 34. Exposition maximale

Crypto Position Sentinel doit encourager des limites.

Exemples pédagogiques :

```text
Exposition crypto totale :
faible / moyenne / élevée / excessive

Exposition par token :
micro / petite / risquée / excessive

Exposition par narratif :
IA / memecoin / L2 / RWA / DePIN / gaming / autre

Exposition par blockchain :
Ethereum / Solana / Base / BSC / autre
```

Le module ne donne pas de seuil personnalisé.

Il demande à l’utilisateur de définir ses limites avant d’être émotionnel.

- holders dumpent ;
- annonce démentie ;
- équipe disparaît ;
- volume chute ;
- narratif s’éteint ;
